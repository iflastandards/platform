# Sitemap Enhancement Plan

## Context

The HTML sitemap pages (`/sitemap`) in each Docusaurus site currently only display "RDF Downloads" and "Blog" links, instead of showing all pages from the site. The sitemap.xml files are complete (e.g., ISBD has 236 URLs), but the HTML sitemap page doesn't render them.

## Current Issue

The existing sitemap.tsx implementation uses `useAllDocsData()` from Docusaurus, but the rendering logic has issues:
- Filters out docs without titles (removing many pages)
- Poor category organization
- Hardcoded "UNIMARC documentation" description (copy-paste error)
- Doesn't display page count
- No tooltips showing relative paths

## Objective

Display all pages in the HTML sitemap with:
- **Page titles** as link text
- **Relative paths** as tooltips (for easy copy/paste)
- **Organized by category** (Elements, Vocabularies, Blog, Documentation, etc.)
- **Total page count** displayed
- **Correct site name** in description

## Research: Docusaurus Sitemap Architecture

### Standard sitemap.xml
- Auto-generated by `@docusaurus/plugin-sitemap` (included in preset-classic)
- Contains: `<loc>`, `<lastmod>`, `<changefreq>`, `<priority>`
- Used by search engines
- Complete and accurate

### HTML Sitemap Page (custom)
- Located in `src/pages/sitemap.tsx` for each site
- Custom implementation (not provided by Docusaurus)
- Uses `useAllDocsData()` hook to get page metadata

### useAllDocsData() Hook
- Returns all document metadata from Docusaurus content plugins
- Includes: id, path, title, sidebar info
- Available for docs, blog posts, and pages
- Already contains all the data we need

### createSitemapItems Hook (alternative approach)
- Available in sitemap plugin configuration
- Allows enhancing sitemap.xml with custom metadata during build
- Could generate additional JSON file with rich metadata
- More complex than needed for this use case

## Recommended Approach

**Fix the existing `useAllDocsData()` implementation** rather than creating new infrastructure.

### Why This Approach?
- ✅ Uses existing Docusaurus infrastructure
- ✅ No build-time sitemap.xml modifications needed
- ✅ No client-side XML parsing
- ✅ Real page titles from document metadata
- ✅ Works with all page types (docs, blog, custom pages)
- ✅ Tooltips show relative paths for copy/paste
- ✅ Simpler than custom sitemap generation

## Alternative Approaches Considered

### Approach A: Enhance sitemap.xml with createSitemapItems
```typescript
// In docusaurus.config.ts
sitemap: {
  createSitemapItems: async ({routes, defaultCreateSitemapItems}) => {
    const items = await defaultCreateSitemapItems({routes});
    // Add custom metadata
    return items.map(item => ({
      ...item,
      // Could add title, description, category here
    }));
  }
}
```

**Why Not:**
- More complex than needed
- Requires modifying 6 docusaurus.config.ts files
- sitemap.xml doesn't support arbitrary metadata
- Would need separate JSON file anyway

### Approach B: Fetch and Parse sitemap.xml on Client
```typescript
// Fetch sitemap.xml and parse with DOMParser
const response = await fetch('/sitemap.xml');
const xmlDoc = parser.parseFromString(xmlText, 'text/xml');
```

**Why Not:**
- Client-side XML parsing is slower
- Doesn't provide page titles (only URLs)
- Would need to derive titles from URLs (poor UX)
- Extra network request on every page load

### Approach C: Generate JSON Sitemap at Build Time
```typescript
// Custom plugin to generate sitemap.json with metadata
{
  "pages": [
    {"url": "/intro", "title": "Introduction", "category": "Docs"},
    // ...
  ]
}
```

**Why Not:**
- Requires custom Docusaurus plugin
- Duplicates data from useAllDocsData()
- More infrastructure to maintain
