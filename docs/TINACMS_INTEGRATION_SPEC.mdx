## Executive Summary

This specification outlines the integration of TinaCMS (Tina) as a visual content management system for IFLA Standards documentation sites. TinaCMS will provide SMEs (Subject Matter Experts) with a user-friendly, visual editing interface while maintaining the existing Git-based workflow and MDX content structure.

## Goals and Objectives

### Primary Goals
1. **Visual Editing Interface**: Provide SMEs with a WYSIWYG editor for MDX content
2. **Preserve Git Workflow**: Maintain existing Git-based collaboration and version control
3. **Element/Vocabulary Management**: Enable visual editing of complex RDF structures
4. **Multi-Site Support**: Centralized editing for all 6 IFLA standards sites
5. **Seamless Integration**: Work with existing Docusaurus + theme architecture

### Success Criteria
- SMEs can edit content visually without technical knowledge
- All changes go through Git review process (PRs)
- Complex structures (elements, vocabularies) are easily editable
- No disruption to existing development workflow
- Performance impact < 200ms for edit mode

### Git Workflow Integration
```typescript
// tina/config.ts - Git integration
export default defineConfig({
  // ... other config
  build: {
    outputFolder: 'admin',
    publicFolder: 'public',
    // Custom build hook for validation
    postBuild: async () => {
      // Validate all MDX files
      await validateMDXFiles();
      // Run linting
      await runLinter();
      // Generate type definitions
      await generateTypes();
    },
  },
  
  // Custom save hooks
  onSave: async ({ collection, document }) => {
    // Create Git branch for changes
    const branchName = `tina-edit-${Date.now()}`;
    await createGitBranch(branchName);
    
    // Commit changes
    await commitChanges(document, `feat: edit ${collection}/${document.id} via TinaCMS`);
    
    // Create PR
    await createPullRequest({
      branch: branchName,
      title: `Content Update: ${document.title || document.id}`,
      body: generatePRDescription(document),
      labels: ['content-edit', 'tina-cms'],
    });
  },
});

async function generatePRDescription(document) {
  return `
## Content Update via TinaCMS

**Document**: ${document.title || document.id}  
**Type**: ${document._template || 'Unknown'}  
**Editor**: ${document._lastModifiedBy || 'System'}

### Changes Made
- Content updated through visual editor
- All validation checks passed
- Ready for review

### Review Checklist
- [ ] Content accuracy verified
- [ ] Links and references working  
- [ ] Formatting and structure correct
- [ ] Follows IFLA standards guidelines

*This PR was generated automatically by TinaCMS integration.*
`;
}
```

### Authentication & Permissions
```typescript
// pages/api/auth/tina.ts
export default async function handler(req, res) {
  // Integrate with existing Clerk auth
  const { userId } = getAuth(req);
  
  if (!userId) {
    return res.status(401).json({ error: 'Unauthorized' });
  }
  
  // Check user permissions
  const user = await clerkClient.users.getUser(userId);
  const hasEditPermission = user.publicMetadata.roles?.includes('editor') || 
                           user.publicMetadata.roles?.includes('admin');
  
  if (!hasEditPermission) {
    return res.status(403).json({ error: 'Insufficient permissions' });
  }
  
  // Generate Tina token
  const tinaToken = generateTinaToken(userId);
  
  res.json({ token: tinaToken, user: { id: userId, name: user.firstName } });
}

// User permission levels
enum UserRole {
  VIEWER = 'viewer',     // Can view content in Tina
  EDITOR = 'editor',     // Can edit content, creates PRs
  REVIEWER = 'reviewer', // Can approve content changes
  ADMIN = 'admin',       // Full access including config
}

// Site-specific permissions
interface UserPermissions {
  userId: string;
  roles: UserRole[];
  sites: string[];  // Which sites user can edit
  collections: string[];  // Which content types
}
```

## Risk Assessment

### High Risk
1. **Git Conflicts**: Multiple editors working on same content
   - **Mitigation**: Branch-per-edit strategy + conflict resolution UI
2. **Performance Impact**: Large vocabulary files
   - **Mitigation**: Lazy loading + pagination + caching
3. **Data Loss**: Corrupted Git operations
   - **Mitigation**: Backup strategy + transaction rollback

### Medium Risk
1. **User Adoption**: SMEs resistant to new interface
   - **Mitigation**: Training + gradual rollout + fallback to GitHub
2. **Schema Evolution**: Changes to MDX structure
   - **Mitigation**: Versioned schemas + migration tools

### Low Risk
1. **TinaCMS Updates**: Breaking changes in TinaCMS
   - **Mitigation**: Version pinning + testing pipeline
