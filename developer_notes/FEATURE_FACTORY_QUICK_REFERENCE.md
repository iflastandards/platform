# Feature Factory Quick Reference

## Overview
The Feature Factory is our structured 4-phase workflow for developing new admin features using TDD and Refine.dev generators.

## Phase 1: Discovery & Refinement
**Goal:** Clarify and confirm requirements through interactive dialogue

### Process:
1. **User provides:** Initial description of the new feature
2. **AI asks:** Clarifying questions to fully understand requirements
3. **Dialogue continues:** Until both parties agree on detailed requirements
4. **AI provides:** Final requirements summary for confirmation

### Questions AI Will Ask:
- [ ] **User Goal:** What is the primary objective for the user?
- [ ] **Data Model:** What new data contracts (Zod schemas) are needed? What are their fields and types?
- [ ] **User Actions:** What actions can the user take? (e.g., create, update, trigger a job, filter a list)
- [ ] **Access Control (RBAC):** Which user roles (e.g., 'admin', 'editor', 'viewer') can access this feature? What specific actions (view, create, edit, delete) can each role perform?
- [ ] **Service Interactions:** Which backend services (e.g., Supabase queues, external APIs) are involved?
- [ ] **Edge Cases:** What happens on success, failure, or with invalid inputs?

### Output:
- Comprehensive requirements summary
- User confirmation before proceeding to Phase 2

## Phase 2: UI Planning & Customization Strategy
**Goal:** Define customizations needed beyond Refine.dev's generated scaffold

### What to Identify:

#### Refine.dev Will Generate:
- Standard list page with table
- Create form with basic fields
- Edit form with basic fields
- Show page with field display
- Basic CRUD operations

#### Needs Customization:
- Special form fields (date pickers, rich text, file uploads)
- Custom validation rules beyond basic required/type
- Table columns with special rendering (badges, formatted dates, actions)
- Advanced filters and search
- Computed/derived values
- Conditional field visibility
- RBAC-based UI elements

#### Needs Addition:
- Dashboard widgets
- Bulk operations
- Import/export functionality
- Custom workflows
- Reports and analytics
- Non-CRUD pages

### Approval Gate:
- User says: **"Customization plan approved"**

## Phase 3: Development Plan & Approval
**Goal:** Technical implementation plan with TDD

### PRD Components:
- **Feature:** One-sentence description
- **User Story:** "As a [role] with [permissions], I want to [action] so that [benefit]"
- **Acceptance Criteria:** Checklist including RBAC

### Technical Task Checklist (11 Steps):
1. **Git Branch:** `git checkout -b feature/[feature-name]`
2. **Contracts:** Define Zod schemas
3. **Tests (RED):** Write failing tests for expected behavior
4. **Fixtures:** Create mock data JSON
5. **Mocks:** Implement MSW handlers
6. **UI Scaffolding:** `npx refine create resource [resource-name]`
7. **Test Scaffold:** Run tests against generated code
8. **UI Customization (GREEN):** Make tests pass
9. **Providers/Adapters:** Implement with validation
10. **Refactor:** Clean up while keeping tests green
11. **Final Tests:** Verify all pass including RBAC

### Approval Gate:
- User says: **"Plan approved. Begin implementation."**

## Phase 4: Implementation & Progress Tracking
**Goal:** Execute plan with TDD workflow

### Process:
1. Start with Task #1 (git branch)
2. For each task:
   - Implement/generate code
   - Present output
   - Show updated checklist with ✓
   - Wait for "Continue"
3. Special pauses:
   - After git branch creation
   - After test writing (RED phase)
   - After Refine scaffolding
   - After each customization

### TDD Checkpoints:
- **Step 3:** Tests must fail (no implementation yet)
- **Step 7:** Some tests pass (from generator), some fail
- **Step 8:** All tests must pass
- **Step 10:** Tests still pass after refactor

## Command Reference

### Git Setup
```bash
git pull origin main
git checkout -b feature/[feature-name]
```

### Refine.dev Generator
```bash
# Basic CRUD
npx refine create resource [resource-name]

# With options
npx refine create resource [resource-name] \
  --actions list,create,edit,show,delete \
  --path /[resource-path]
```

### Testing During Development
```bash
# Watch mode during TDD
pnpm nx test admin --watch

# Run specific test file
pnpm nx test admin --testFile=[Component].test.tsx

# Check what fails after scaffolding
pnpm nx test admin --grep "[feature-name]"
```

### Validation Commands
```bash
# Type checking
pnpm typecheck

# Linting
pnpm lint

# All tests
pnpm test
```

## Common Customizations After Generation

### Add Contract Validation
```typescript
const { data } = await dataProvider.getList('resources');
const validated = data.map(item => ResourceContract.parse(item));
```

### Add Permission Checks
```typescript
const { can } = usePermissions();
if (!can('edit', 'resources')) {
  return <AccessDenied />;
}
```

### Add Custom Filters
```typescript
const { tableProps, filters } = useTable({
  filters: {
    initial: [
      { field: 'status', operator: 'eq', value: 'active' }
    ]
  }
});
```

### Add Business Logic

## Quick Tips

1. **Always start with tests** - They define your requirements
2. **Keep generated code recognizable** - Mark custom sections clearly
3. **Test after each step** - Don't wait until the end
4. **Use mock data first** - Switch to live data last
5. **Validate everything** - Use Zod contracts everywhere
6. **Check permissions early** - RBAC should be in initial tests
7. **Refactor often** - Keep code clean as you go
8. **Document customizations** - Help future developers

## When to Deviate

You may skip the full Feature Factory workflow when:
- Making small bug fixes
- Updating existing features
- Adding single fields to existing forms
- Fixing test failures

Always use Feature Factory for:
- New CRUD resources
- New major features
- Complex forms or workflows
- Features requiring new API endpoints
- Features with complex RBAC requirements
